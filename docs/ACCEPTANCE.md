# Критерии готовности к публичному запуску

Ни один пункт пока не отмечен выполненным. Проверять на финальной реализации.

- [ ] На целевой GPU (**RTX 2060**, типично **6 ГБ** VRAM) через `docker compose --profile gpu-probe` определены реальный объём VRAM, совместимые драйвер/CUDA/PyTorch и RTF GigaAM (`docs/GPU_PROBE.md`). Замеры с 3060 Ti / 4090 Laptop не засчитывать.
- [ ] Распознавание 4-часовой записи не держит полный waveform в GPU и укладывается в RAM/VRAM.
- [ ] После предзагрузки всех весов работает при запрещённом исходящем интернете.
- [ ] Проверены тишина, шум, телефонная речь, музыка, несколько голосов, битый и переименованный файл.
- [ ] Проверена реальная запись Телемоста WebM, в том числе без длительности в метаданных; расчёт основан на извлечённом звуке.
- [ ] Для видео без звука и неподдержанного кодека выводится понятная ошибка до оплаты.
- [ ] Выбор дорожки в многодорожечном видео соответствует прослушиванию, цене и результату.
- [ ] Скачиваемый WAV корректно воспроизводится, исходное видео не изменяется; пользователь видит формат 16 кГц/моно.
- [ ] Границы сегментов не теряют и не дублируют слова; SRT/VTT имеют корректные смещения.
- [ ] После рестарта задания восстанавливаются, fencing блокирует старый worker.
- [ ] Два одновременных подтверждения не тратят один остаток дважды.
- [ ] Повтор POST /jobs не создаёт дополнительный резерв.
- [ ] Success/cancel и retry/success не создают двойного списания или бесплатного опубликованного результата.
- [ ] Ошибка и отсутствие речи освобождают резерв.
- [ ] Изменение тарифа не влияет на подтверждённую цену.
- [ ] Проверены округления: 1 сек → 1 коп., 61 сек → 7 коп., 17:42 → 107 коп., 60 мин → 360 коп. при 6 коп./мин.
- [ ] Повторные и переставленные webhooks, поддельная сумма, неверный магазин и отменённый платёж не зачисляют деньги.
- [ ] Потеря webhook устраняется сверкой с провайдером.
- [ ] Возврат, частичный возврат и падение между этапами корректно восстанавливаются.
- [ ] Пользователь A не получает файл, текст, события и экспорт пользователя B.
- [ ] Пройдены CSRF, session fixation, rate limit и сценарии отзыва сессий.
- [ ] Reset token одноразовый; журнал не содержит секретов и текста записей.
- [ ] Пользовательские пути и медиаконтейнеры не дают доступа к файловой системе и сети.
- [ ] Лимиты применяются к потоку загрузки и декодированному объёму, а не только Content-Length.
- [ ] Истечение хранения удаляет оригиналы, промежуточные данные и результаты по выбранной политике.
- [ ] HTTPS и туннель переживают перезапуск; Windows сон/обновление не оставляют невидимо зависший сервис.
- [ ] База и файлы восстановлены из резервной копии на чистой установке.
- [ ] Пройдены мобильный сценарий, клавиатура, контраст и reduced motion.
- [ ] Документы оператора, чеки, платёжный магазин, правила возврата и политика хранения утверждены.
- [ ] Определены модель/сервис имеющейся кассы и поддерживаемый маршрут интеграции; проверены реквизиты оператора и автоматические интернет-расчёты.
- [ ] На каждую фискальную операцию назначен один маршрут: эквайер или прямой API; двойной чек исключён.
- [ ] Проверены аванс, зачёт по отдельным заданиям, частичный и полный возврат по утверждённой схеме.
- [ ] Тайм-аут после принятия чека кассой не вызывает повторной фискализации.
- [ ] Падение между денежной транзакцией и отправкой чека восстанавливается через outbox.
- [ ] При недоступной кассе платёж и чек имеют независимые состояния, оператор получает сигнал, соблюдается утверждённый порядок обработки сбоев.
- [ ] Чек доступен только владельцу, содержит корректные реквизиты и не раскрывает название или текст аудиозаписи.
