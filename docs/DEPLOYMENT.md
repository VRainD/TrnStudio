# Перенос «Горизонта» на другую машину

Контейнер версии 0.2.0 содержит интерфейс, локальный HTTP API, FFmpeg и FFprobe. Работают извлечение аудио, WAV и калькулятор 0,06 ₽/мин. GigaAM, авторизация, эквайринг и касса пока не реализованы и не включены в образ. PostgreSQL и очередь из целевой архитектуры подключаются вместе с backend, сейчас они не нужны.

Проверено 16.09.2026: Docker-сборка, запуск Compose, healthy-статус и браузерный сценарий через контейнер — извлечение WebM, воспроизведение WAV, ошибка для видео без звука, новый тариф и мобильная вёрстка.

## Windows 11

Установить Docker Desktop с Linux containers/WSL2. Для будущего GPU worker нужны драйвер NVIDIA с поддержкой WSL и GPU passthrough. Текущая обработка FFmpeg работает на CPU, GPU не занимает.

Скопировать весь проект, кроме `.git`, `.qa` и `.local-media`, открыть терминал в его папке:

```powershell
Copy-Item .env.example .env
docker compose up -d --build
docker compose ps
```

Открыть http://127.0.0.1:4180. Сменить порт можно в `.env`. Слушается только loopback хоста. Это подготовка к переносу, не публичный production-деплой: до публикации требуется авторизация и изоляция медиадекодера из основной спецификации. Контейнер использует непривилегированного пользователя, ограничение ресурсов, healthcheck и ротацию логов.

## Перенос без интернета

После успешной сборки на исходной машине:

```powershell
docker save --output gorizont-studio-0.2.0.tar gorizont-studio:0.2.0
Get-FileHash gorizont-studio-0.2.0.tar -Algorithm SHA256
```

Скопировать архив, `compose.yaml` и `.env.example` на целевой компьютер. Сверить SHA256, затем:

```powershell
docker load --input gorizont-studio-0.2.0.tar
Copy-Item .env.example .env
docker compose up -d --no-build --pull never studio
```

Базовая сборка требует интернета; импорт готового образа — нет. Архитектура целевого компьютера должна совпадать с образом (обычно linux/amd64). Версионированный готовый образ фиксирует фактические версии пакетов; повторная сборка Dockerfile может получить обновления базового тега и apt.

## Проверка GPU отдельно

```powershell
docker compose --profile gpu-check run --rm gpu-check
```

Ожидается таблица NVIDIA с целевой видеокартой. Это только проверка проброса, не тест GigaAM. При офлайн-переносе образ `nvidia/cuda:12.4.1-base-ubuntu22.04` нужно предварительно скачать и перенести отдельно. На Linux нужен NVIDIA Container Toolkit; Windows использует интеграцию Docker Desktop/WSL2.

## Эксплуатация

```powershell
docker compose logs --tail 100 studio
docker compose restart studio
docker compose down
```

Временные файлы находятся в `media_temp` и очищаются после выдачи результата. При аварийном завершении возможны остатки; volume не предназначен для постоянного хранения записей. `docker compose down` сохраняет volume. Не использовать `down -v`, если временные данные нужны для диагностики. Пока нет фонового уборщика, периодически контролировать место на диске Docker.

Один файл за раз, до 1 ГБ и 4 часов, до 5 минут на декодирование. Выход — WAV 16 кГц/моно для распознавания, не исходное качество. После рестарта незавершённое извлечение требуется повторить. До публичного запуска добавить очередь, автоматическую очистку после сбоев и проверку лимитов декодирования в отдельном изолированном worker.
